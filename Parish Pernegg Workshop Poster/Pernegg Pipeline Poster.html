Pernegg, all 43 books: OCR and decision pipeline on one A100

Chandra OCR 2 reads the pages while Perplexity Decider Flash v1.2 (4B) checks each record as soon as it is parsed. Both models stay loaded together, so nothing is unloaded between stages.

Pipeline: every stage runs at the same time, pages move through on disk

1 · DOWNLOAD

Matricula images

1 process, 4 threads, 1 s pause. About 0.56 pages/s, so the remaining 2,809 pages take about 1.4 h and stay ahead of OCR.

2 · SPLIT

Left / right halves

smart_split_lossless.py on 8 CPU processes. Lossless, no resizing.

3 · OCR

Chandra OCR 2

One vLLM server, 16 requests in flight. This is the bottleneck.

4 · PARSE

HTML to rows

convert_html_to_xlsx.py on 8 CPU processes. Each row goes to the decider queue.

5 · DECIDE

Decider Flash 4B

8 requests in flight, one question per request: type, surname vs RTB list, date check, review flag.

6 · WRITE

xlsx + review list

Existing Excel schema, plus surname suggestion, probability and an abstain flag.

Each page carries a status marker (downloaded, split, OCR done, parsed, decided). A crash or restart resumes at the first unfinished page. Generative German transcription stays in stage 3 and parsing; the decider only chooses between options.

Chandra, util 0.72. Measured 31 GiB at util 0.38 with 8 requests. Raising it to 0.72 grows the KV cache to about 40 GiB. Each request needs roughly 2 GiB of cache (about 16k tokens, 131 KB per token), so about 16–19 requests fit.
Decider Flash. Measured peak 12.8 GiB (8.5 GB weights, the rest is activations). Start Chandra first, then the decider in the remaining 28%.
Spare 8 GiB for CUDA graphs and fragmentation. This is the reason for 16 in flight, not 19.

OCR. Phase 1 shows about 40 s per page with one request at a time, which would be about 41 h for 3,700 pages. Running 16 together should give roughly 5–8×, so 0.125–0.2 pages per second, which is 5–8 h; at only 4× it is about 10 h (lighter bar). Decisions. Each finished OCR half is parsed and sent to the decider at once, and its rows are written to the Excel file straight away. At about 0.2 pages per second and 10 questions per page, that is about 2 requests per second against a measured 67 ms each, so the decider is busy about 13% of the time and never builds a queue. The run therefore ends about 2 minutes after the last OCR result. Pilot. The 10-page pilot replaces the 5–8× assumption with a measured number.
